      How it works

      From a published file to a proof anyone can check.

      1. Publish

        A department registers a product with a signed data contract: schema, quality rules, readers and permitted purposes. Data that breaks the contract is refused.

      2. Chunk

        FastCDC splits the file at content-defined boundaries. Each chunk is stored under the SHA-256 of its bytes, so an edit only disturbs the chunks around it.

      3. Seal

        Chunk hashes form an RFC 6962 Merkle tree. The manifest, holding the root, the contract and the lineage, is signed and anchored in a hash-chained audit log.

      4. Derive

        Another department transforms verified inputs. The transformation's code hash, parameters and purpose are signed into the output, pinned to each input's Merkle root.

      5. Verify

        A consumer re-hashes every chunk, checks every signature against a pinned authority, walks the full history and, when something is wrong, lists every product it reached.
